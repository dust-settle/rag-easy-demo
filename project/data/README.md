## 两种用法

**A. 用现成分片**（推荐，省一步切分）：直接读 `kb_chunks.jsonl`，一条一个 document，`id` 作为主键，`type` 可做 metadata 过滤。

**B. 用全文自行切分**：把你的切分器指向 `英冠4.0牛奶客服知识库-全文.md`，按 `###` 标题切，标题下的整段就是一个 chunk——文档已按“一个标题=一个完整答案”写，天然对齐。

## 分片里的结论字段

- `type`：`product` / `nutrition` / `audience` / `usage` / `policy` / `sop` / `faq`
- `verified`：继续沿用，用于控制生成口径
  - `high`：官方或国标可查，可直接对外
  - `medium`：需与商品页/包装核对，回答时要带“以实物包装为准”
  - `low`：价格、促销等会变动的信息，不得输出确定数值

按 `type` 分 collection（如 `policy` 单独一库）会让“能不能退”这类问题更准，不会被营养段落抢占 Top-K。
